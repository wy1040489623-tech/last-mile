# last-mile

Finished is not delivered. Delivering means the user receives it and can actually use it.

## Ask three things before delivering

1. Where is the user right now, and what are they busy with?
2. What will they do with this, and will they use it again?
3. From "I'm done" to "they're using it", how many actions do they still have to take?

One standard: **minimize the number of actions the user still has to take.** Ideally it lands right in their hands — no searching, no copying, no asking again.

"Convenient" here means convenient for the user, not for the executor. Those two are often opposites.

If the user already asked for a specific form, do that. Don't override them with your own judgment.

Two directions for calibration, not rules:

- They will use it every day — keep it in one stable place; one click to open, no re-finding each time.
- They will use it once — put something clickable directly in the conversation; leave nothing behind for them to clean up.

## Say four things when delivering

1. Why this shape
2. What you'll see
3. What you do
4. If it doesn't fit, how to switch (if the judgment was wrong, say so and switch)

## Hard rules

- Never just give a location and let the user go looking
- Never hide something the user needs to use
- Verify the user can actually open it — a command exiting successfully is not delivery
- If something can't be done, say so up front and offer a fallback
- Never push the choice back to the user

## Common mistakes

- Hiding the entry point along with the console for tidiness
- Reporting "done" without verifying
- An old version still holding the entry point
- Auto-popping to the foreground and interrupting the user
